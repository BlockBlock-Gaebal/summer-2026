# 갓생 내기 — 의지력에 돈을 거는 습관 챌린지 프로토콜

돈을 예치하고, 매일 체크인하고, **실패하면 언제 실패했는지에 따라 다르게 잃는다.**
Sui Move로 작성한 온체인 정산 프로토콜입니다.

> 연세대학교 블록체인 동아리 블록블록 · 2026 여름 프로젝트

---

## 핵심 아이디어 — 실패에 등급을 매긴다

기존 습관 챌린지는 성공/실패 이분법입니다. day 1에 포기한 사람과 day 29까지 버틴 사람이
똑같이 전액을 잃습니다. 억울하고, 무엇보다 **후반부에 버틸 이유를 주지 못합니다.**

이 프로토콜은 탈락 시점을 환급률로 번역합니다. day $d$에 탈락한 참가자의 환급률은
**완주일수** $k = d - 1$을 입력으로 하는 볼록결합 커브입니다.

```
R(k) = α·(k/D) + (1−α)·(k/D)²        α = 0.2, k = d − 1
```

선형항과 이차항의 볼록결합이고, α 하나가 곡률을 조절합니다. 이 형태를 고른 이유는
**"하루 더 버티는 것의 가치"가 뒤로 갈수록 커져야 하기 때문**입니다 (노력 비용은 후반에 올라가니까).

| D=30, 예치 10 SUI | day 1 버티기 | day 30 버티기 |
|---|---|---|
| 하루의 가치 | 0.076 SUI | 0.591 SUI |

**마지막 하루가 첫날의 7.8배.** 이게 이 커브의 전부입니다.
커브 입력이 탈락일 $d$가 아니라 완주일수 $k = d-1$인 것도 같은 이유입니다 —
$d$를 그대로 쓰면 마지막 날에 실패해도 완주자와 똑같이 전액을 돌려받게 되어
(= 마지막 날 무임승차) 마지막 하루의 금전적 가치가 정확히 0이 됩니다.

**완주자만 원금 전액에 도달합니다.**

## 스트리밍 분배 — 몰수금을 나눠주는 방식

몰수금을 종료 시점에 몰아서 나누지 않습니다. day $d$에 발생한 몰수액을
**남은 $(D-d+1)$일에 걸쳐 균등 방출**하고, 매일의 방출량을 그날의 생존자에게 지분 비례로 귀속시킵니다.

두 가지가 따라옵니다.

1. **배당 흐름이 단조증가한다.** 이탈이 초반에 몰리든 후반에 몰리든, 일일 배당 총량은 뒤로 갈수록 커집니다. 즉시 분배였다면 보상이 초반에 쏠려 "비용은 오르는데 보상은 내려가는" 역방향 구조가 됩니다.
2. **중도 포기의 기회비용이 확정액이 된다.** day 25의 포기자는 "누가 탈락하면 받았을지도 모르는 돈"이 아니라 **이미 발생해서 내 몫으로 흘러오던 돈의 남은 5일치**를 버립니다.

"재분배 지분은 버틴 기간에 비례한다"는 성질이 별도 규칙 없이 스케줄 자체에서 나옵니다.

### 예시 (D=5, 3인 각 10 SUI, α=1.0)

B가 day 2에, C가 day 4에 탈락하고 A가 완주하면:

| | A (완주) | C (day4 탈락) | B (day2 탈락) |
|---|---|---|---|
| 수령 | **20.0** | **8.0** | **2.0** |

C는 탈락했지만 생존 기간에 쌓인 배당 2.0은 그대로 가져갑니다. A는 C가 못 받은
스트림 잔여분까지 흡수합니다. 합은 정확히 30 SUI — **∑수령 + dust = ∑예치**가
모든 시나리오 테스트의 최종 검증 조건입니다.

## 왜 블록체인인가

이런 정산은 중앙 운영자가 하기 어렵습니다. 복잡할수록 "제대로 계산했나", "쟤만 봐준 거 아닌가"라는
신뢰 문제가 커지기 때문입니다.

실제로 일어난 일이기도 합니다. 미국의 운동 내기 앱 **GymPact(Pact)**는 회사가 예치금을 쥐고
성공/실패를 판정하는 구조였는데, 성공한 사용자에게도 요금을 부과하다 FTC 제재를 받고
(소비자 환불 $948,788 명령) 폐업했습니다. **중앙화된 커스터디 + 판정의 신뢰가 실제로 무너진 사례입니다.**

이 프로토콜은 그 두 가지 — 돈의 보관과 정산 규칙 — 를 컨트랙트에 넘깁니다.
체크인 판정만 오라클 주소가 결과를 제출하는 방식으로 오프체인에 남깁니다.
이 경계 덕분에 나중에 무엇을 붙이든(백엔드 자동화 / 커뮤니티 투표 / AI 판정) 컨트랙트는 불변입니다.

## 저장소 구조

```
contracts/godsaeng/       Move 패키지 — 정산 로직 + 테스트
frontend/                 읽기 전용 대시보드
scripts/                  오라클 · 데모 자동화
docs/
├─ DECISIONS.md           확정 결정 + 현재 상태 (정본)
├─ PROJECT_CONTEXT.md     배경 · 리서치 · 경쟁 분석
├─ 정산_프로토타입/         커브 유도, 구현 스펙, 시뮬레이터, 그래프
└─ 발표/                   발표 자료
members/                  팀원 소개
```

설계의 출발점이 궁금하면 `docs/정산_프로토타입/01_설계문서/01_CURVE_DESIGN_ver1-3.md`부터 읽으면 됩니다.
커브를 "방향 선택"이 아니라 **인센티브 조건에서 유도되는 함수족**으로 다룬 문서입니다.

## 실행

```bash
# Sui CLI 필요 (https://docs.sui.io/guides/developer/getting-started/sui-install)
cd contracts/godsaeng
sui move test
```

정산 수식의 파이썬 미러도 함께 둡니다. Move 코드와 연산 순서·절단 시점까지 1:1로 대응하므로,
Sui CLI 없이도 기대값을 검산할 수 있습니다.

```bash
cd docs/정산_프로토타입/03_시뮬레이터
python3 run.py
```
