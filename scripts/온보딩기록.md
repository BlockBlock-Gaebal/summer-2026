## 1. 🔴 빈 방에 `submit_results`를 호출하지 않는다

가장 중요한 규칙이다. **한 번 어기면 그 방은 영구히 못 쓴다.**

참가자가 0명인 상태에서 `submit_results`를 호출하면,
생존자 지분합이 0이 되어 컨트랙트가 **전멸로 판정**한다.
그러면 `status`가 즉시 `ENDED`로 바뀌고 되돌릴 방법이 없다 (`challenge.move:245`).

컨트랙트에 가드를 넣을지 검토했으나 **넣지 않기로 확정**했다 (D-22).
재배포 비용이 크고, 데모는 사전 세팅으로 진행하므로 발표 중 발생 경로가 없기 때문이다.
즉 **이건 코드가 막아주지 않는다. 사람이 지켜야 한다.**

**순서를 지킬 것:**

```
create_challenge  →  참가자 join (전원)  →  submit_results
```

실행 전에 참가자 수를 확인하는 습관을 들이면 안전하다:

```bash
npm run read-state -- <CHALLENGE_ID>
```

참가자가 0명이면 `read_state.ts`가 경고를 띄운다.

⚠️ **최초 생성분 `0xfb1eb049…`가 실제로 빈 방이다.** 이 ID로 submit하면 그대로 터진다.
개발·리허설에는 검증용 방 `0xcc48adc4…`를 쓸 것.

## 2. 코인 오브젝트가 1개면 split이 실패한다 → PTB로 해결

가스로 쓰는 코인과 예치용 코인이 같은 오브젝트면 `sui client split-coin`이 실패한다.

8/9 회의에서는 "faucet을 여러 번 받아 코인 오브젝트를 늘린다"로 정했으나,
**testnet faucet CLI가 폐지되어 이 대책은 무효**다 (아래 3번).

**확정 해법은 PTB에서 가스 코인을 직접 쪼개는 것이다** (D-24).
코인 오브젝트가 1개뿐이어도 동작한다:

```bash
sui client ptb \
  --split-coins gas "[100000000]" \
  --assign stake \
  --move-call <PKG>::challenge::join @<CHALLENGE_ID> stake.0 \
  --gas-budget 30000000
```

`--split-coins gas`는 가스 코인에서 쪼개는 것이라 별도 코인이 필요 없고,
쪼갠 결과(`stake.0`)를 같은 트랜잭션에서 바로 `join`에 넘긴다.
쪼갤 코인 = 가스 코인이라는 충돌 자체가 사라진다.

실제로 코인이 1개뿐인 `verify-b` / `verify-c` 주소가 이 방식으로 join에 성공했다.

## 3. testnet faucet CLI는 폐지되었다

```
$ sui client faucet --address 0x6a2b4679…
For testnet tokens, please use the Web UI: https://faucet.sui.io/?address=0x6a2b4679…
(exit: 1)
```

브라우저에서 캡차를 통과해야 해서 **스크립트로 자동화할 수 없다.**

→ 주소를 매번 새로 파지 말고 **`verify-b` / `verify-c` 두 개를 고정 재사용**한다.
충전이 필요하면 이미 SUI를 가진 주소에서 `pay-sui`로 분배한다:

```bash
sui client pay-sui \
  --input-coins <보유코인ID> \
  --recipients <주소1> <주소2> \
  --amounts 200000000 200000000 \
  --gas-budget 10000000
```

정말 잔고가 마를 때만 Web UI로 한 번 받는다.

## 4. `submit_results`는 탈락자가 없는 날도 호출해야 한다

시간 검증이 없어서 **호출 자체가 day 진행**이다 (수동 카운터).
탈락자가 없으면 빈 vector로 호출한다. 총 `total_days`회 호출해야 `finalize`가 가능하다.

첫 `submit_results` 호출이 `PENDING → ACTIVE` 전환점이고, 그 전까지만 `withdraw`가 가능하다 (D-08).
