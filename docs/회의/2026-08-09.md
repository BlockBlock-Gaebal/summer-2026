## 2. 결정 사항

상세는 `docs/DECISIONS.md` 참조. 요약:

1. **인터페이스 프리즈 선언** — 함수 시그니처 / 이벤트 필드 / struct 필드가 대상. 배포 ID·파라미터 값·내부 구현·UI는 비대상
2. **대시보드 1순위 확정** — CLI 실연 경로는 제거하지 않고 유지 (백업)
3. **대시보드는 읽기 전용** — 지갑 서명 트랜잭션 미구현
4. **데모는 사전 세팅 상태에서 시작** — 무대에서 방 생성/참여 안 함
5. **표시용 계산은 프론트, 금액 계산만 온체인**
6. **배포 ID 정본 = `docs/DEPLOYMENT.md`**
7. **참가자 Table 조회 스크립트는 진모가 공용 제공**

## 3. 미결 / 보류

- [ ] **빈 방 `submit_results` 가드 추가 여부** (판단: 진모)
  - 넣는 경우: 재배포 → ID 갱신 → 전원 통보. **승준 착수 전에 완료해야 함**
  - 안 넣는 경우: 컨트랙트 동결 유지. 운용 규칙("빈 방에 submit 금지")으로 회피
  - 데모는 사전 세팅으로 진행하므로 발표 중 발생 가능성은 없음
- **day1 탈락자 claim abort** — 버그 아님. `k = d-1` 커브상 완주일수 0 → 환급 0이 정의된 동작. 대시보드에서 버튼 비활성 + "전액 몰수" 표시로 처리 (승준)
- **코인 오브젝트 1개일 때 split 실패** — faucet 복수 수령으로 코인 분할 후 진행, 또는 `pay-sui` 사용. 온보딩 문서 반영 완료

## 4. 다음 회의까지 각자 할 일

### 진모 (컨트랙트 / 설계)

컨트랙트 구현은 완료 상태. 이번 구간의 본업은 **다른 파트 언블록 + 발표 자산**.

1. **`scripts/read_state.ts` (최우선)**
   - Challenge ID 입력 → 참가자 배열 출력
   - `getDynamicFields` → `getDynamicFieldObject` 2단계 조회
   - 프론트·오라클 공용
   - **완료 정의**: 실행하면 참가자들의 주소 / stake / failed_day / claimable이 콘솔에 출력된다
2. **문서 PR** — `DEPLOYMENT.md` 신규 + `DECISIONS.md` 갱신 + 본 회의록. 리뷰어 승준·유안 둘 다
3. **가드 패치 여부 최종 판단** — 넣는다면 승준 착수 전에 완료
4. (여유) 발표 5분 대본 초안

### 유안 (오라클 / 데모) — 승준보다 먼저 나와야 함

승준이 화면을 검증하려면 **상태가 실제로 변해야** 한다. 전원 생존 상태로는 탈락 표시·claimable 확인이 불가하므로 이 파트가 선행.

1. **`scripts/seed.ts`** — 방 생성 + 3인 join 자동화
   - 리허설마다 새 방을 파야 하므로 수동 진행은 비현실적
   - 실행할 때마다 **동일한 상태**가 재현되어야 함
   - 코인 오브젝트 복수 확보 후 진행 (split 실패 회피)
   - **완료 정의**: 명령어 한 줄로 새 방 + 3인 참여 상태가 만들어진다
2. **`scripts/submit.ts`** — day별 탈락자 제출
   - 시나리오: day1 B탈락 / day3 C탈락 / A완주
   - **완료 정의**: 실행 후 `read_state.ts`에서 failed_day와 claimable 변화가 확인된다
3. **데모 대본 v1** — 5분 안에 무엇을 어떤 순서로, 누가 말하고 누가 조작하는지 (초안 수준)

### 승준 (대시보드) — 크리티컬 패스

읽기 전용. 트랜잭션 전송 미구현.

| 순위 | 작업 | 완료 정의 |
|---|---|---|
| 1 | vite + dapp-kit 세팅, Testnet RPC 연결 | Challenge 오브젝트가 콘솔에 찍힘 |
| 2 | ID를 config 한 곳으로 분리 | 코드 내 ID 하드코딩 0건 |
| 3 | **참가자 목록 표 렌더** | 주소/예치금/상태가 표에 표시 ← **최소 성립선** |
| 4 | 방 정보 표시 | current_day / vault / status |
| 5 | claimable + 탈락일 | day1 탈락자 0원 표시 |
| 6 | 새로고침 or 폴링 | submit 후 값이 갱신됨 |
| 7 | 디자인 | — |

- 참가자 조회는 진모의 `read_state.ts`를 받아서 사용. 혼자 붙잡지 말 것
- 환급률 등 파생값은 프론트에서 계산
- 디자인은 마지막. 데이터가 먼저
- PR은 단계별로 쪼갤 것 (1~3을 한 PR로 묶지 않기)
