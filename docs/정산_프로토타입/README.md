## 그래프 재생성

`04_그래프/`의 그림 12장은 커밋되어 있다. 파라미터를 바꿔 다시 뽑으려면 아래대로 한다.

**환경 준비.** Ubuntu 24.04부터는 PEP 668 때문에 시스템 파이썬에 `pip install`이 막힌다
(`error: externally-managed-environment`). venv를 쓴다:

```bash
cd docs/정산_프로토타입/03_시뮬레이터
python3 -m venv .venv && source .venv/bin/activate
pip install numpy pandas matplotlib
```

그래프 라벨이 한글이므로 한글 폰트가 없으면 글자가 전부 □로 깨진다. 최초 1회:

```bash
sudo apt install fonts-nanum
```

**실행.** 스크립트마다 출력 위치가 다르다:

| 스크립트 | 생성 | 출력 위치 |
|---|---|---|
| `godsaeng_sim.py` | 5장 (`01_`~`05_`) | `03_시뮬레이터/figures/` |
| `godsaeng_sim_v4.py` | 5장 (`v4_1`~`v4_5`) | `03_시뮬레이터/figures/` |
| `alpha_sweep.py` | 2장 (`03_alpha_sweep_tradeoff`, `04_staying_wage_by_alpha`) | **`04_그래프/`에 직접 저장** |

앞의 둘은 `figures/`에 떨어지므로, 그 내용을 `04_그래프/`로 옮겨야 설계문서의 이미지 링크
(`../04_그래프/파일명.png`)가 맞는다. `alpha_sweep.py`는 옮길 필요 없이 바로 덮어쓴다.

2. **`01_설계문서/02_VER4_DESIGN.md`** — 중도 참여를 열면 생기는 세 가지 문제(회계/커브시계/타이밍게임)와 세 가지 설계안(개방형/빈티지분리/NAV진입가) 비교. 명제 5~8. 1번 문서를 읽었다는 전제로 씀.
3. **`02_스펙/PROTO_SPEC.md`** — **(아카이브)** 위 설계를 Move 코드로 어떻게 짰는지의 **구현 당시** 스펙. ver1~5 각각의 상태 모델, 함수 시그니처, 기대값이 하드코딩된 테스트 시나리오. 구현은 이미 끝났고 본문은 갱신하지 않으므로, **지금 무엇이 확정값인지는 `docs/DECISIONS.md`를 봐야 한다.** 이 문서는 "왜 이렇게 구현되어 있나"를 되짚을 때 읽는다.
4. **`03_시뮬레이터/`** — 위 두 설계문서의 모든 수치·그래프가 나온 소스. 눈으로 검산하거나 파라미터를 바꿔 새 시나리오를 뽑을 때 여기를 돌린다. 넷의 용도가 다르니 구분해서 쓸 것:

   | 도구 | 용도 |
   |---|---|
   | `mirror.py` | **기준 구현.** `challenge.move`의 파이썬 미러(연산 순서·절단 시점 1:1). 직접 돌리는 게 아니라 아래 셋이 정답지로 삼는다. **수식을 바꾸면 여기부터 고친다** |
   | `run.py` | **기대값 전체 회귀.** 커브·파라미터·정산 규칙을 건드렸으면 여기부터 돌린다. 테스트 기대값은 이 출력에서 가져온다 |
   | `alpha_sweep.py` | **α 근거.** α는 최적화 값이 아니라 목표 배율에서 역산하는 값이므로(D-28), α를 건드릴 때 새 값이 목표 배율 구간 안인지 확인한다 |
   | `verify_onchain.py` | **온체인 대조.** 배포된 방의 실측값을 미러와 맞춰본다. 새로 배포·관통했을 때 쓰며, 실측값 미입력(`ACTUAL = None`) 상태로 돌리면 "이 값이 나와야 한다"는 기대값만 미리 뽑아준다 |

## 핵심 설계 요약 (한 화면 정리)

**정산 방식**: 몰수금을 즉시 나눠주지 않고 잔여 기간에 걸쳐 균등 방출하는 **스트리밍(베스팅) 분배**.

**몰수 커브**: `R(k) = α·(k/D) + (1−α)·(k/D)²,  k = d − 1` — 선형과 이차의 볼록결합. **커브 입력은 탈락일 d가 아니라 완주일수 k다** (D-05: day1 탈락 → 환급 0, 완주만 전액). α는 "얼마나 볼록한가"를 조절하는 유일한 파라미터, **확정값 α=0.2** (D-06).

**중도 참여 (ver4, 스트레치 골)**: 커브는 개인 잔여기간으로 정규화(강제됨 — 안 그러면 완주해도 손해 보는 "기부 함정" 발생). 늦게 들어올수록 유리해지는 "찍먹 차익" 문제가 있고, MVP는 **개방형 + 참여 마감선**으로 방어, 공개방 정공법은 **빈티지 분리**(로드맵).

**한 줄 요약**: "커브 방향을 고른 게 아니라, 인센티브 조건(생존 임금이 노력 비용을 이겨야 한다)을 정의하고 그 조건을 만족하는 함수족을 유도했다."
